### 1. ZRUP sign-flip (root cause of multi-week 1°/s stationary drift)

**File:** `app/src/main/cpp/EKFState.cpp` (around line 617)
**Change:** `H = -I` on b_g rows → `H = +I` on b_g rows.
**Why it was wrong:** Comment at 614-616 conflated `residual = z - h(x_est)` with `linearization = h(x_est+δx) - h(x_est)`. Standard error-state Kalman: `H = ∂h/∂δx = +I` for direct bias observation `h(x)=b_g`.
**Falsifier passed:** 374/374 ZRUP fires now show residual shrinking (was growing). Stationary `b_g.z` stays near zero throughout 60s of stillness.

### 5. V-SHAPE ROOT CAUSE — IMUPreintegrator leading-gap zero-bug 🎯

**File:** `app/src/main/cpp/IMUPreintegrator.cpp:274-284` (within `integrate()`)
**The bug:** loop iterates over `[start_ns, end_ns]`; first iteration had `gi == 0`, so `if (gi > 0) w = …` left `w = (0,0,0)` for the leading sub-interval `[start_ns, first_gyro_sample_ts]`. At ω ≈ 0.25 rad/s walking rate × 2 ms gap × 30 fps × 132 s = ~115° of missed rotation over a two-loop walk.
**Fix:** zero-order forward hold — if `gi == 0` use `g_samples[0]` (and same for accel `ai==0` → `a_samples[0]`).

### Deep dive: WHY did V-shape fix break LC? (mechanism hypothesis)

The V-shape fix is in `IMUPreintegrator::integrate()` — it changed `deltaR` to be ~25% larger (the leading-gap gyro is no longer dropped). `deltaR` is consumed by THREE downstream sites:

1. **EKF.propagateIMU** (rotation state) — fixed, working ✓
2. **Clone storage** (R_GtoI propagates into clone_R) — fixed, working ✓
3. **`klt_.track(..., imu_delta.deltaR, K, win_sz)` at `Tracker.cpp:1474`** ← suspected regression source

`klt_.track` uses `deltaR` for IMU-aided point prediction:
```cpp
// In TrackKLT::track:
predictPoints(prev_pts, predicted_pts, delta_R, K);  // applies H = K · delta_R · K^-1
curr_pts = predicted_pts;  // initial guess for KLT iteration
```

Then `cv::calcOpticalFlowPyrLK(...)` starts from `curr_pts` and refines. KLT does FB-consistency check (FB_CHECK_THRESH=4 px² = 2 px tolerance).

**Pre-fix:** `delta_R` was under-rotated. Predicted points moved LESS than reality. KLT searched in a position too close to prev_pts. For slow walking, this worked. For fast turns, KLT had to iterate further but FB-check passed.

**Post-fix:** `delta_R` is accurate. Predicted points move full amount. For fast turns this is CORRECT. But:
- If the prediction lands OUTSIDE the image (e.g., a feature on the right edge that the camera is rotating away from), KLT drops it
- If the prediction lands far from the actual feature location due to non-linear motion within the frame (parallax during translation), the FB-check (2 px tolerance) is tight enough to reject what was previously a valid track

**Net effect:** more KLT feature dropouts during turns → `tracked` count fluctuates lower → condition B (`tracked < MIN_FEATURES/2`) fires more often → keyframe rate doubles (179 → 362) → BoW DB dilutes → per-match scores fall ~10× (0.026 → 0.003) → no match passes adaptive minScore → LC accepts 0.

**Secondary observation:** 36% of v53 keyframes have `kp=0` (ORB returning empty). May be partially correlated — when KLT is dropping features rapidly, keyframes may be stored at moments when the camera was framing low-texture scenes (floor, sky, blurred). The `ORB_KP0` diagnostic will tell us.

**Hypothesized fix paths (in priority order, validated by v54 data):**
1. If `KF_STORE` shows `cond_B` firing >30% of stores → **loosen the trigger** (e.g., `tracked < 30` instead of `< 40`, OR remove condition B entirely and rely only on the 15-frame cadence). Restoring keyframe rate to v50 levels should recover BoW scores.
2. If KLT prediction is the underlying issue → consider PASSING A DAMPED deltaR (e.g., `0.7 * deltaR + 0.3 * eye()`) to KLT to bias toward conservative predictions while still using accurate deltaR for EKF propagation. ROOT CAUSE FIX — but more invasive.
3. If `ORB_KP0` shows image is fine (mean 40-200, stddev > 20) but ORB returns empty → lower `ORB_FAST_THRESHOLD`.

**DO NOT** revert the V-shape fix — it's the correct fix for the propagation math. The fix should be at the KLT/keyframe-gate layer, not at the propagation layer.
